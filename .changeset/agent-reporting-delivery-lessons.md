Agents answer status questions with Yes, No, or Not yet first, end a message that leaves work running with what is watched, how, and until when, and show a draft in full when it changed, is short and pending, or is requested as final, never as patches or a pointer. Before presenting a review or recommendation they run every check they can and say what they checked, correct every place an earlier claim reached when a decision changes it, treat exploratory questions as discussion rather than instructions, and say what happens if a requested hold or ordering is skipped. They act on an unprovable precondition only when a wrong guess is cheap and the first step tests it, check related work when feedback names one instance of a problem, never call a version latest from memory, start independent work instead of idling, and keep unanswered user questions across compaction.

The orchestrator verifies each premise before it goes into a brief, gives delegates a size budget, points briefs at standing rules instead of pasting them, reshapes the design after two rounds of point fixes, reruns an unrelated CI failure once before reporting it, and keeps a held PR as a quiet open draft. The `create-pull-request` ready check now requires a correctness pass over the whole diff and no unresolved review thread, fixes correctness findings by default, gives merge steps unasked, and re-reads the approval state after every push. Reviewers check duplicate, out-of-order, or retried events and partial failure.
