# ADR-CORE-037: Hooks as Deterministic Reinforcement

## Status

Accepted (2026-11-03). Confidence: medium.

## Context

The consolidated plugin shipped no hooks ([CORE-034](ADR-CORE-034-consolidated-declarative-plugin.md): "Do not add executable scaffolding merely because a host supports it"), and the capability contract listed hooks as "intentionally absent; no concrete capability requires them". Three concrete needs now exist:

- **Always-on core on Claude Code and ZCode.** Neither host lets a plugin ship always-on rules, so the core arrived only through the mode commands, and a session without a mode command ran without it. Both hosts add a plugin `SessionStart` hook's output to the context and re-run it after `/clear` and compaction.
- **Rules a model can skip.** Protected-branch commits, force pushes, hook bypasses, discarding work, hand-editing generated files, and email addresses in PR text are always-on rules, and a model can still miss them on a long turn. A `PreToolUse` hook checks every matching call.
- **Project customization.** `.maestria/workflow.md` and `.maestria/rules.md` are a promised feature; outside OpenCode and Pi they reach the session only if the model follows a text instruction to read them.

A host capability re-check on 2026-11-03 ([register](../../plugin-host-verification.md)) found plugin-shippable hooks on Claude Code, ZCode, Codex, Cursor, Devin, and Kimi Code, code-only hooks on OMP, native hooks on OpenCode and Pi, and no portable hooks on Hermes. Hosts differ in events, decisions (only Claude Code, ZCode, and Cursor's shell hook can ask the user), trust (Codex skips plugin hooks until the user trusts them), and failure mode (Devin and Kimi fail open).

## Decision

Ship hooks on every host that supports them, as deterministic reinforcement of rules that stay in the directives. A hook is never a rule's only home: the rule text remains the fallback wherever a hook fails open, is untrusted, or is disabled.

- **One shared script per job, thin host adapters.** The jobs are core loading, project customization, the git-safety classifier, the generated-file guard, and the email scan. Their pure policy lives once in `packages/shared/hook-policy` and is transpiled into the plugin's `hooks/lib/policy.mjs`; `hooks/lib/hosts.mjs` maps each host's input and decision format. OpenCode (`tool.execute.before` and `permission.evaluate`) and Pi (`tool_call` and `user_bash`) apply the same git classifier in their native adapters, and Pi's `before_agent_start` injects the always-on core.
- **Core loading** on Claude Code and ZCode: a `SessionStart` hook with matcher `startup|resume|clear|compact` prints the core as two parts, each under Claude Code's 10,000-character limit for one hook output, so the core returns after `/clear` and compaction. Their mode commands then carry only the mode body. Hosts that already load the core always-on get no core hook.
- **Project customization**: a `SessionStart` hook prints `.maestria/workflow.md` then `.maestria/rules.md` from the session's project root on Claude Code, ZCode, Cursor, Devin, and Codex. Mid-session edits apply after `/clear` or compaction (OpenCode and Pi re-read every turn).
- **Git safety**: block `git commit --no-verify`/`-n`, `git push --no-verify`, and a one-off `git -c core.hooksPath=... commit` or `push` (setting it with `git config core.hooksPath`, as setup tools such as husky do, stays allowed); ask before commits or pushes to `main`, `develop`, `staging`, or `release/*`, force pushes (`--force`, `-f`, `--force-with-lease`, `+refspec`), `git reset --hard`, `git clean -f`, `git checkout -- <path>`, `git restore <path>` (not `--staged` alone), and `git stash drop`.
- **Generated-file guard**: ask before an edit or write tool changes a file whose first five lines after any frontmatter carry `@generated`, `DO NOT EDIT`, `Do not edit directly`, or `Generated by/from`. Scripts that regenerate files are unaffected.
- **Email scan**: ask before `gh pr`/`gh issue` create, edit, or comment, `gh api` fields, or `git commit` messages that contain an email address other than a noreply address.
- **Ask where possible.** Where a host or event has no ask (Codex, Kimi Code, Devin, Cursor's `preToolUse`), ask becomes block with a message that the user's approval is needed. Opting out means disabling the plugin's hooks with the host's own control; there is no maestria environment variable.

OMP hooks are executable extensions rather than declarative files, so the OMP module is a follow-up. Hermes portable packages cannot ship hooks; it keeps the text rules.

## Consequences

- Positive: Claude Code and ZCode sessions get the always-on core without a mode command, after `/clear`, and after compaction; risky git commands and generated-file edits meet a check on every matching call; project customization reaches five more hosts without relying on the model.
- Negative: the package now ships executable Node scripts, so a host without `node` on `PATH` silently skips them (they fail open, and the rules still apply). Each matching tool call spawns a short Node process. Codex users must trust the hooks before they run, and any plugin update asks again. Behavior differs by host because ask becomes block where ask is unsupported.
- Neutral: hooks never widen what a host allows; host permissions still decide. Opting out is per host. The classifier reads the command line it is given: a git command hidden inside `bash -c "..."` or `$(...)` is not classified, so the text rules remain the only check there.
- Live behavior is unverified on every host; the [register](../../plugin-host-verification.md) lists the checks to run.

## Alternatives Considered

- **Keep hooks absent**: no executable surface, but Claude Code and ZCode keep running without the core outside mode commands, and the git and generated-file rules rest on model attention alone.
- **Hooks as the only home of these rules**: smaller directives, but hooks fail open on several hosts and can be disabled, so the rules would vanish exactly when the hook does not run.
- **A per-host script for each job**: simpler per file, but the policy would drift between hosts; one policy module keeps the classifier identical everywhere.
- **Claude Code output styles or a plugin main-thread agent for the core**: both are always-on channels, but they replace Claude Code's own instructions or the user's agent setting.

## Supersession

Supersedes the "hooks intentionally absent" stance in [CORE-034](ADR-CORE-034-consolidated-declarative-plugin.md) and its capability contract. Builds on [CORE-036](ADR-CORE-036-always-on-core-and-skill-map.md), which defines the always-on core the hooks load.
