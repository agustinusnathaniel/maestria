maestria defines a main loop and one reviewer specialist. The main loop investigates, designs, implements, and delivers each outcome itself, loading method skills when a task needs them. Only reviewer remains as a separate agent, for independent blind review of meaningful changes. Native profiles and tool controls vary by host; role guidance alone is advisory. On Agent Plugins hosts the main session takes the main-loop role through the global policy, so [`@maestria/agent-plugins`](/agent-plugins/) ships reviewer as a profile; [OpenCode](/opencode/) registers both. Direct-route turns execute on the host; platform invocation syntax lives in the plugin documentation.

## Main-Loop Model

The main loop owns each outcome end to end: it investigates the code, designs the change, implements it, and drives delivery. It loads method skills instead of handing work to a role: `recon` before changing code it has not read or when the affected surface is unclear, `architecture-plan` for trade-offs or a multi-phase plan, and `diagnose` for a bug with an unknown cause. It dispatches only reviewer, for independent blind review of meaningful changes.

For a more independent check, give reviewer a different model from the main session with [`maestria configure`](/cli/commands/#configure), for example `maestria configure opencode --set reviewer=<model-id>`.

For multi-slice implementation, it plans reviewable PR boundaries early and commits coherent slices after validating them. Each PR receives its own review and evidence; the integrated outcome receives final verification. When an `architecture-plan` design guides implementation, the main loop first presents a concise design brief so the user can understand the intended changes, sequence, and trade-offs. Tables or diagrams are used when they help explain the design.

The full method groups the work into three concerns:

- **Understand** - reconnaissance, diagnosis, design, planning
- **Make** - implementation, documentation
- **Check** - independent validation, quality gates

The main loop handles understand and make itself with skills; the check terminates when reviewer accepts the result.

See [When to Use maestria](/core/when-to-use/) for when review is worth its coordination cost.

## Modes

Three workflow modes control method depth; activation and enforcement depend on the platform:

| Mode | Full Form | Pipeline | Use Case |
| --- | --- | --- | --- |
| **fein** | Full method | `recon` and `architecture-plan` skills -> implementation in the main loop -> required blind review | Production-grade work, mandatory validation |
| **sonar** | Research only | `recon` or `architecture-plan` in the main loop, read-only, change no files and dispatch no subagents - STOP before implementation | Understanding before committing |
| **blitz** | Fast implementation | Direct execution in the main loop when permitted; otherwise the permitted specialist, skipping optional skill loads but keeping required safeguards and review. | Quick fixes, known territory |

The modes are defined by ModeKeyword in `packages/shared/pi/src/state-core.ts` as the full-method, research-only, and fast modes. Where keyword detection is supported, mode keywords are recognized anywhere in a message and case-insensitively; matches inside code fences or inline code are ignored, and the most restrictive mode wins when several appear (full-method over research-only over fast).

## Specialist Reference

| Specialist | Role | When to Use | Key Constraints |
| --- | --- | --- | --- |
| **Main loop** | Investigator, designer, maker, and owner - investigates, designs, implements, and delivers each outcome itself | Every task; loads `recon`, `architecture-plan`, or `diagnose` when the task needs them | Does recon, design, diagnosis, and implementation itself. Dispatches only reviewer. Presents an `architecture-plan` design before dependent edits. |
| **Reviewer** | Code review - correctness, edge cases, security, performance, maintainability | Post-implementation validation, pre-merge review, security audit | Read-only - cannot edit; one general review plus only risk-matched lenses, with blind review, observation-first verification, and [fix]/[dismiss]/[escalate] triage |

## Portable Utilities

The consolidated [Agent Plugins package](/agent-plugins/) exports two portable utilities, `handoff` for transferring task context and `iteration-limits` for bounding repair loops, alongside the [bundled methodology skills](#bundled-methodology-skills). Each is generated from the matching section of the global rules, so it always states the same policy the full integrations carry. Full methodology uses host-specific native profiles, commands, and policy entry points. Portable utilities alone do not activate this roster or its modes.

## Skills

### Bundled methodology skills

The rules and the main loop name five maestria method skills, so every maestria package ships them: `@maestria/agent-plugins` (Claude Code, Codex, Cursor, Kimi Code, Devin, ZCode, OMP, Hermes), `@maestria/opencode`, and `@maestria/pi`. They update with the package; there is nothing extra to install or select.

- **[create-pull-request](https://github.com/agustinusnathaniel/maestria/blob/main/packages/core/agent-directives/skills/create-pull-request/SKILL.md)** - Title, body, and visual-evidence conventions for a reviewable PR. Agents load it before drafting when the task owns an active PR, follow the project template while preserving the required information, and stop on explicit project opt-out.
- **[docs-update](https://github.com/agustinusnathaniel/maestria/blob/main/packages/core/agent-directives/skills/docs-update/SKILL.md)** - Documentation and changeset procedure. Agents load it before finishing a change to behavior, interfaces, configuration, or user-facing workflows, and follow it to classify and update affected docs; ordinary docs work proceeds without it.
- **[diagnose](https://github.com/agustinusnathaniel/maestria/blob/main/packages/core/agent-directives/skills/diagnose/SKILL.md)** - Systematic debugging that traces errors from symptom to root cause. The main loop loads it for a bug, regression, failure, or crash with an unknown cause.
- **[recon](https://github.com/agustinusnathaniel/maestria/blob/main/packages/core/agent-directives/skills/recon/SKILL.md)** - Maps unfamiliar code before a change: entry points, call chains, boundaries, and every consumer the change must reach. The main loop loads it before changing code it has not read.
- **[architecture-plan](https://github.com/agustinusnathaniel/maestria/blob/main/packages/core/agent-directives/skills/architecture-plan/SKILL.md)** - Compares approaches and writes a phased plan, including rollback for migrations and rollouts. The main loop loads it for trade-offs, boundaries, ADR decisions, and multi-phase work, and presents the plan before dependent edits.

Supported agents get these skills with their maestria plugin; that is the recommended install. Only for an agent maestria does not package, install them with [skills.sh](https://skills.sh); this offers the plugin's seven skills, including `handoff` and `iteration-limits`:

```bash
npx skills add agustinusnathaniel/maestria
```

Earlier CLI versions installed these two skills separately for each agent. `maestria update` and `maestria uninstall` now remove the copies the CLI installed, and `maestria doctor` lists any that remain; copies you installed yourself are left alone.

### Optional engineering skills

Agents load these when the assignment calls for them. Every one is optional: a missing skill never blocks the work, and the core directives still apply.

The main loop loads **[architecture-decision-framework](https://github.com/agustinusnathaniel/skills/tree/main/skills/software-engineering/architecture-decision-framework)** when a consequential trade-off benefits from a structured comparison. It lives in the separate [agustinusnathaniel/skills](https://github.com/agustinusnathaniel/skills) repository with other general-purpose engineering skills. That repository is independent of maestria and ships all its skills as one plugin for Claude Code, Codex CLI, Cursor, Kimi Code, ZCode, OMP, and Devin. In Claude Code:

```bash
/plugin marketplace add agustinusnathaniel/skills
/plugin install agustinusnathaniel-skills@agustinusnathaniel-skills
```

Its [README](https://github.com/agustinusnathaniel/skills#installing-skills) covers the other hosts. To pick individual skills instead, use [skills.sh](https://skills.sh) (drop `-g` to install into the current project):

```bash
npx skills add agustinusnathaniel/skills -g
```

The main loop also loads community skills on a matching trigger, such as `agent-browser` for UI verification or `tdd` for explicit test-driven work. The list lives in the Skills section of the [main-loop and reviewer definitions](https://github.com/agustinusnathaniel/maestria/tree/main/packages/core/agent-directives/specialists); install any of them from their own sources if you want that behavior.
