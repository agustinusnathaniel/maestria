With `@maestria/deepseek` installed, start the web app in your project directory:

```bash
dsh web
```

<Aside type="caution" title="Choose the route that fits the task">
  Review adds model work and waiting time. Use [When to Use maestria](/core/when-to-use/) before
  sending a small task or an expensive, slow model through the full method.
</Aside>

## Run a Task

<Steps>

1. Start a new session on the **maestria** preset and describe the task. The main loop investigates, designs, and implements in that session; no prefix is needed.

2. Before delivering a meaningful change, it calls `maestria_reviewer`. The reviewer runs in the background on its own preset, with only read, search, and skill tools, and its findings return to the session when it finishes.

3. To choose the route yourself, start the message with a mode: `fein` for the full method, `sonar` for research that stops before implementation, or `blitz` for the fast path on familiar work.

</Steps>

Project rules in `.maestria/workflow.md` and `.maestria/rules.md` at the repository root reach every turn; edits apply on the next step.

Some commands meet a check before they run: git hook bypasses such as `git commit --no-verify` are refused, and commits to protected branches, force pushes, discarding work, edits to generated files, and email addresses in commit or PR text wait for your approval in DeepSeek Harness. Everything else follows its sandbox, approvals, and permission presets.
