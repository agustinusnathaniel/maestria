`@maestria/agent-plugins` packages Maestria's agents, workflow commands, policy, and utility skills in one directly installable directory. Each host uses its own supported resources. Through the portable [Agent Plugins v1 format](https://agent-plugins.org/specification), this package exposes two [Agent Skills](https://agentskills.io/specification): `handoff` and `iteration-limits`.

<Aside type="tip" title="Choose the host guide for the full methodology">
  Portable installation supplies utilities. Native host integrations add specialist profiles,
  workflow entry points, and policy through the host's supported interfaces. Use the guide for your
  client before installing.
</Aside>

## Choose Your Host

| Host | What the installation provides | Guide |
| --- | --- | --- |
| Claude Code | Seven native specialists, three native workflow commands, two utilities | [Claude Code](/agent-plugins/claude-code/) |
| Codex | Two plugin utilities; companion CLI installs seven native agents and global routing instructions | [Codex](/agent-plugins/codex/) |
| Cursor | Seven native specialists, workflow commands, always-apply policy and routing, two utilities | [Cursor](/agent-plugins/cursor/) |
| Kimi Code | Seven native specialists, workflow commands, session bootstrap, two utilities | [Kimi Code](/agent-plugins/kimi-code/) |
| Devin | Root agent profiles and policy; two utilities plus three host-specific workflow skill exports | [Devin](/agent-plugins/devin/) |
| ZCode | Selected native profiles and workflow commands, two utilities | [ZCode](/agent-plugins/zcode/) |
| Oh My Pi | Eight task profiles, three commands, always-apply policy and routing, two utilities | [Oh My Pi](/agent-plugins/omp/) |
| Hermes | Two portable utilities; optional manual host context configuration | [Hermes](/agent-plugins/hermes/) |

[OpenCode](/opencode/) and [Pi](/pi/) retain their separate native runtime packages. The [compatibility matrix](/agent-plugins/compatibility/) distinguishes documented resources, package validation, loader probes, and live runtime verification.

See the official [compatible clients](https://agent-plugins.org/compatible-clients) list for portable format support; the matrix above describes Maestria resources, not live verification.

## Portable Utilities

| Skill              | Purpose                                                              |
| ------------------ | -------------------------------------------------------------------- |
| `handoff`          | Transfer the outcome, constraints, evidence, blockers, and next step |
| `iteration-limits` | Bound repair and review loops with explicit termination conditions   |

These utilities live at `skills/<name>/SKILL.md`. Portable clients choose their invocation syntax and qualified names. Loading them does not register specialist agents, activate routing, or create workflow commands. Agent Plugins v1 standardizes skills and optional MCP configuration; its portable contract does not provide native subagent registration or declare native agents, commands, rules, or hooks. This package ships no MCP server.

## Stage and Validate the Package

<AllPackageManagers type="dlx" pkg="maestria@latest" args="plugin install" />

Install `@maestria/agent-plugins` through the selected client using its package installer or the staged directory. The exact activation command depends on the client.

The command prints a staged directory for your client's installer or local-plugin setting. Staging does not activate the plugin or change client configuration. To validate an existing directory:

<AllPackageManagers type="dlx" pkg="maestria@latest" args="plugin validate /path/to/plugin" />

A successful check reports a valid manifest and the two utility skills. Use `--json` for a machine-readable report. `maestria install <host>` performs the host-specific installation described in that host's guide.

The command is intentionally namespaced as `maestria plugin ...`: `maestria install` manages runtime integrations and host installation flows; `maestria plugin` validates and stages artifacts.

## Install from a Checkout

Point the host at the package directory containing `plugin.json`:

```text
/path/to/maestria/packages/agent-plugins/
```

The checkout and extracted npm archive share the same installation root. Follow the host's enable and trust flow, then reload plugins or start a new session. Install this bundle once per host namespace; remove the superseded standalone integration to avoid duplicate resources.

## Runtime Boundaries

Native profiles and commands contain their complete methodology, so they do not depend on role or global-rules skill preloads. Host permissions, sandboxing, delegation, trust, and session lifecycle remain host controls. The package includes no executable runtime adapter, lifecycle hooks, recurring automations, or MCP server. Those components are intentionally absent; their absence does not mean the host lacks them.

If utilities do not appear, confirm the selected directory contains `plugin.json` and `skills/`, check host trust settings, and reload discovery. For native resources, use the host guide's verification steps.
