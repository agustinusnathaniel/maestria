`@maestria/agent-plugins` packages maestria's reviewer profile, workflow commands, policy, and skills in one directly installable directory. Each host loads the resources it supports. Through the portable [Agent Plugins v1 format](https://agent-plugins.org/specification), the package also exposes eight [Agent Skills](https://agentskills.io/specification): the `handoff`, `review-loop`, `implement`, `create-pull-request`, `docs-update`, `diagnose`, `recon`, and `architecture-plan` [method skills](/core/agents/#skills) the main loop's skill map tells agents to load, copied from maestria's core methodology.

<Aside type="tip" title="Native hosts get the full methodology">
  Portable installation supplies the eight skills. Native host integrations add one reviewer
  profile, three workflow modes, and policy through the host's own interfaces. Choose your host in
  [Installation](/agent-plugins/installation/) before installing.
</Aside>

## What you get

- **One reviewer:** the independent review profile, embedding its complete role and the global policy. The main loop investigates, designs, implements, and delivers itself, loading the method skills its skill map names (`recon`, `architecture-plan`, `diagnose`, `implement`, `docs-update`, `create-pull-request`, `handoff`, `review-loop`) when their trigger applies.
- **Three workflow modes:** the full-method, research-only, and fast modes defined by ModeKeyword in `packages/shared/pi/src/state-core.ts`.
- **Always-on policy and routing,** on hosts that can load it.
- **Eight skills:** `handoff`, `review-loop`, `implement`, `create-pull-request`, `docs-update`, `diagnose`, `recon`, and `architecture-plan`, on every host.

Start with [Installation](/agent-plugins/installation/), then see [Usage](/agent-plugins/usage/) for commands and dispatch.

## Hosts at a glance

| Host | Reviewer | Workflow modes | Always-on policy | Read-only roles |
| --- | --- | --- | --- | --- |
| [Claude Code](/agent-plugins/installation/#claude-code) | 1 reviewer | 3 native commands (`/maestria:fein` and others) | In the commands | Write and Edit tools denied |
| [Codex](/agent-plugins/installation/#codex) | 1 reviewer, via the companion CLI | Mode keywords | Managed block in global instructions (companion CLI) | Prompt-level (Codex no longer applies a role's `sandbox_mode`) |
| [Cursor](/agent-plugins/installation/#cursor) | 1 reviewer | 3 commands | Always-apply rule | Declared, not enforced for plugin agents |
| [Kimi Code](/agent-plugins/installation/#kimi-code) | 1 reviewer | 3 commands | `systemPromptPath` to `kimi.system-prompt.md` | Write and Edit tools denied |
| [Devin](/agent-plugins/installation/#devin) | 1 reviewer profile, local only | 3 mode skills (`/maestria:fein` and others) | Root `AGENTS.md` (Devin reads 16 KiB) | Prompt-level |
| [ZCode](/agent-plugins/installation/#zcode) | 1 reviewer | 3 commands | In the profile and commands (no rules component) | Write and Edit removed from subagent tools; shell remains |
| [OMP](/agent-plugins/installation/#omp) | 1 reviewer task profile | 3 commands | Always-apply rule | Prompt-level |
| [Hermes](/agent-plugins/installation/#hermes) | None | None | Optional manual context | Not applicable |

Every host also gets the eight skills. Codex marketplace installation supplies only the skills; the reviewer profile and routing come from `maestria install codex`. Hermes supplies the skills, with optional [manual context](/agent-plugins/installation/#hermes-manual-context) for routing.

[OpenCode](/opencode/) and [Pi](/pi/) keep their separate native runtime packages. The [compatibility matrix](/agent-plugins/compatibility/) distinguishes documented resources, package validation, loader probes, and live runtime verification. See the official [compatible clients](https://agent-plugins.org/compatible-clients) list for portable format support; the table above describes maestria resources, not live verification.

## Skills

| Skill | Purpose |
| --- | --- |
| `handoff` | Brief a delegate, retry a failed delegation, and track work across sessions |
| `review-loop` | Brief the reviewer, triage findings, and bound repair passes |
| `implement` | Implementation judgment, behavior-level testing, and comments |
| `create-pull-request` | Draft or revise a pull request title and body |
| `docs-update` | Keep documentation and changesets in step with a change |
| `diagnose` | Trace a failure to its root cause before fixing |
| `recon` | Map unfamiliar code before changing it |
| `architecture-plan` | Compare approaches and write a phased plan with rollback |

These skills live at `skills/<name>/SKILL.md` and are copied from maestria's core methodology. Portable clients choose their invocation syntax and qualified names. Loading them does not register specialist agents, activate routing, or create workflow commands. Agent Plugins v1 standardizes skills and optional MCP configuration; its portable contract does not provide native subagent registration or declare native agents, commands, rules, or hooks. This package ships no MCP server.

## Runtime boundaries

Markdown hosts share the reviewer profile in `agents/reviewer.md` and one command set in `commands/` (Claude Code and ZCode use the body-only `modes/`, since a SessionStart hook loads their policy). Profiles and commands contain their complete methodology, so they do not depend on role or global-rules skill preloads. OMP and Cursor keep their own rule files because their formats differ; each host that reads a plain session file gets its own, holding the always-on core and only its own host note within that host's cap: root `AGENTS.md` for Devin, `codex.agents.md` installed by the CLI for Codex, `hermes.context.md` added manually for Hermes, and `kimi.system-prompt.md` through `systemPromptPath` for Kimi Code. Host permissions, sandboxing, delegation, trust, and session lifecycle remain host controls. The package includes no executable runtime adapter, recurring automations, or MCP server. Its [hooks](/agent-plugins/usage/#hooks) reinforce rules the directives already state.
