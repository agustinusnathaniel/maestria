The ZCode integration uses the `@maestria/agent-plugins` package. Its `.zcode-plugin/plugin.json` manifest selects the shared `agents/`, `commands/`, and `skills/` directories: seven complete specialist profiles, three native workflow commands, and two utility skills. Profiles embed role and policy; commands embed mode, router, and policy. They are the same `agents/<role>.md` and `commands/*.md` files other Markdown hosts use.

## Install

Stage the plugin in a directory beside a ZCode marketplace file:

```bash
mkdir -p ./maestria-zcode
```

<AllPackageManagers
  type="dlx"
  pkg="maestria@latest"
  args="plugin install --destination ./maestria-zcode/plugin"
/>

Create `./maestria-zcode/marketplace.json` with this entry:

```json
{
  "name": "maestria-local",
  "plugins": [
    {
      "name": "maestria",
      "source": "./plugin"
    }
  ]
}
```

In ZCode, open a workspace, then choose **Settings → Plugins → Create → Add marketplace** and select the `./maestria-zcode` directory. Find **maestria** in the **Personal** section and click **Install**. Staging alone does not install or activate the plugin. See [ZCode's plugin guide](https://zcode.z.ai/en/docs/plugin) for the current UI labels and marketplace format.

## Use

Choose the native fein, sonar, or blitz command from ZCode's prompt picker and supply your goal. Use the native subagent controls to dispatch adventurer, architect, builder, diagnose, planner, reviewer, or writer with a complete task handoff. The Skills group exposes handoff and iteration-limits utilities.

See the [specialist reference](/core/agents/) for role guidance and the [portable package guide](/agent-plugins/) for the two shared utilities.

## Limits

The package adds no MCP server, hooks, or executable runtime extension. ZCode has no plugin rules component, so profiles and commands carry their own complete policy. Adventurer, architect, planner, and reviewer declare `disallowedTools: [Write, Edit]`, which ZCode enforces by removing those tools from the subagent's tool list (verified in the ZCode source; not live-run). Shell access remains, so this is a tool filter, not a sandbox. ZCode drops unknown keys such as `readonly` and `subagents`. Profiles set no `model`, so ZCode uses the main conversation's model. There is no sandbox. A plugin installed locally does not follow a remote workspace by default; use ZCode's **Sync Plugin** control for that workspace. Live ZCode runs were not performed; the loading and enforcement claims come from the ZCode source. See the [compatibility notes](/agent-plugins/compatibility/).
