Devin reads `@maestria/agent-plugins` through `.devin-plugin/plugin.json`. The package supplies complete conventional root agent profiles and always-on policy and routing in root `AGENTS.md`. The manifest declares only `skills`, which adds the two utilities.

## Install

Stage a validated package:

<AllPackageManagers type="dlx" pkg="maestria@latest" args="plugin install" />

Install the printed directory through Devin:

```bash
devin plugins install --local /path/to/staged-plugin
devin plugins info maestria
```

`--local` links the directory on this machine. For personal plugin sync to cloud sessions and other devices, use the repository subdirectory:

```bash
devin plugins install agustinusnathaniel/maestria#packages/agent-plugins
```

Changes apply to new sessions. Use **Reindex plugins** on Devin's Customize page to refresh the web listing. See the [official installation formats](https://docs.devin.ai/cli/extensibility/plugins/overview) and [Customize guide](https://docs.devin.ai/product-guides/plugins).

## Use

Devin has no plugin commands component, so there are no `/maestria:fein` style commands. Trigger a mode with a natural-language keyword that the always-on policy routes:

| Mode keyword    | Purpose                                 |
| --------------- | --------------------------------------- |
| `fein: <goal>`  | Full route with independent review      |
| `sonar: <goal>` | Research and stop before implementation |
| `blitz: <goal>` | Smallest safe implementation route      |

The `handoff` and `iteration-limits` utilities load as skills. Root `AGENTS.md` carries the router, mode definitions, and global policy; there are no role or global-rules skill facades.

In local CLI and Desktop sessions, dispatch native specialist profiles through Devin's subagent controls. Each profile includes complete role and global policy; carry task constraints and evidence in the handoff.

## Limits

Native plugin agents load in local CLI and Desktop sessions, not cloud sessions. Personal plugins can supply the selected skills and policy to cloud sessions, but their presence does not add native plugin subagents there. Devin offers an `allowed-tools` allowlist but no denylist or read-only field, so read-only roles are prompt-level only. No executable adapter, hooks, MCP server, or automation ships here. Live Devin loading remains unverified; package checks establish shipped resources only.
