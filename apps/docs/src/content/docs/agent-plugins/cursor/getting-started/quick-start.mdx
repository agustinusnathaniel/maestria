After installing and reloading the plugin, the selected always-apply native rule supplies complete routing and global policy. Native profiles and commands embed their full methodology; no orchestrator or role skill preload is needed.

<Aside type="caution" title="Full orchestration is not always the best path">
  Direct execution or one specialist is often better for small changes and expensive models. Read
  [When to Use maestria](/core/when-to-use/) before starting `/fein`.
</Aside>

## Try a workflow command

In Agent chat (IDE or CLI):

```text
/fein Fix the flaky auth test and review the fix
```

That selects the full route, adding reconnaissance and design when needed, followed by implementation and independent review.

Other modes:

| Command         | Behavior                                    |
| --------------- | ------------------------------------------- |
| `/sonar <goal>` | Research only - stops before implementation |
| `/blitz <goal>` | Smallest safe route with required review    |

## Try a single specialist

> "Use the builder agent to add a JSDoc comment to the `add` function in `src/math.ts`."

The main agent spawns `builder` via `Task` with a complete handoff.

## Try maker/checker

> "The login flow throws on empty email. Trace the bug, fix it, and review the fix."

Expected sequence:

<Steps>

1. `diagnose` - find the root cause, apply the confirmed minimal fix, and verify it
2. `reviewer` - independent validation (read-only; must not edit)

</Steps>

Never ask the same agent that implemented to review its own work.

The two utility skills are `handoff` and `iteration-limits`. Native resource loading is documented and package-checked; live Cursor verification remains open.
