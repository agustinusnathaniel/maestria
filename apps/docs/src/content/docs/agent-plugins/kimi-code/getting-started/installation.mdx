The Kimi integration ships in `@maestria/agent-plugins`. Its manifest points at the seven shared profiles in `agents/`, the three shared workflow commands in `commands/`, and the session bootstrap in `rules/kimi-code/bootstrap.md`. Root `skills/` contains the two utilities.

## Prerequisites

Use a Kimi Code version supporting native plugin agents, commands, and `systemPromptPath`. See the [official plugin guide](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/plugins.html). Node.js 22.12 or later and npm are needed for the maestria CLI. Package checks confirm the emitted contract; live Kimi loading and model behavior remain unverified.

## Install and Reload

<AllPackageManagers type="dlx" pkg="maestria@latest" args="install kimi-code" />

Inside Kimi Code, reload plugins or start a new session:

```text
/reload
/plugins list
/plugins info maestria
```

Confirm `maestria` is enabled and exposes its native specialists and commands. For manual installation, extract `npm pack @maestria/agent-plugins@latest`, run `/plugins install <extracted-directory>`, then `/reload`.

## What Loads

| Component | Purpose |
| --- | --- |
| Seven native specialists | Complete role and global policy for adventurer, architect, builder, diagnose, planner, reviewer, and writer |
| Three native commands | Complete fein, sonar, and blitz workflows with task arguments |
| `systemPromptPath` bootstrap | Complete policy, routing, and mode guidance within Kimi's 32 KB contribution limit |
| Two utilities | `handoff` and `iteration-limits` |

The integration uses neither `sessionStart.skill` nor `skillInstructions`. Native specialists replace the former mapping to built-in coder, explore, and plan agents. Child methodology does not depend on a parent loading role skills.

## Tool and Model Boundaries

Adventurer, architect, planner, and reviewer profiles use `disallowedTools` to deny `Write` and `Edit`, the tool names registered by Kimi `v0.38.0` source. Earlier releases of this package listed `WriteFile` and `StrReplaceFile`, which matched nothing, so read-only was not effective before. Kimi ignores the other hosts' `readonly` and `model` keys, and substitutes `$ARGUMENTS` in plugin commands. This native tool filter is not a shell sandbox and has not been live-run. Kimi owns permission decisions and execution safety. The plugin-agent format has no per-agent model field, so the host selects the model. The package adds no executable hooks or MCP server.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Plugin missing | Run `/plugins list` and `/plugins info maestria`; verify the installation directory |
| Old skills or agents appear | Remove the former standalone plugin, then `/reload` or start a new session |
| Bootstrap does not load | Confirm the host supports `systemPromptPath` and the selected bootstrap file exists |
| Native role missing | Confirm the host supports plugin agents and the manifest points at `./agents/` |
| Reviewer can edit through a shell | Native write-tool denial does not restrict shell execution |
