After [installation](/agent-plugins/kimi-code/getting-started/installation/), run `/reload` or start a new session. The selected bootstrap supplies complete policy and routing. No global-rules skill preload is needed.

## Choose a Workflow

Select the plugin's native fein, sonar, or blitz command from Kimi's command picker and supply the task. Use the exact names shown by your host.

| Command | Use                                                            |
| ------- | -------------------------------------------------------------- |
| `fein`  | Full route for substantial work with independent review        |
| `sonar` | Research and planning, stopping before implementation          |
| `blitz` | Smallest safe route for familiar work with required safeguards |

Each command contains the complete mode, router, and policy, and preserves task arguments. For example, choose sonar to trace authentication and report findings without editing.

## Delegate to a Native Specialist

```text
Use the adventurer plugin agent to trace authentication in src/auth/.
Return the relevant files, call paths, and uncertainties. Do not edit.
```

Kimi's Agent tool uses the selected native identities `adventurer`, `architect`, `builder`, `diagnose`, `planner`, `reviewer`, and `writer`. Each profile already contains complete role and global policy. Pass the concrete task scope, constraints, and acceptance evidence in the handoff.

After implementation, delegate independent review to `reviewer`. Adventurer, architect, planner, and reviewer profiles deny Kimi's native write/edit tools; shell execution remains a host boundary. Kimi chooses the model because plugin profiles do not support a per-agent model field.

## Use Utilities

The two shared skills, `handoff` and `iteration-limits`, support context transfer and bounded repair. They do not replace the native agents or commands.

These steps follow the packaged native contract. Live Kimi loading remains unverified; see [compatibility](/agent-plugins/compatibility/).
