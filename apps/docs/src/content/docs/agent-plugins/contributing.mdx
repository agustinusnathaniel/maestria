For repository setup, changesets, and pull requests, see the [Contributing Guide](/core/contributing/).

## Ownership

Canonical role, mode, routing, and policy text lives in `packages/core/agent-directives/`. The consolidation generator (`scripts/sync-consolidated-plugin.ts`) composes it with the hand-authored manifest, profile, and native metadata inputs under `packages/agent-plugins/generation/` and writes the installable resources at the package root. Do not edit emitted resources; change a generation input or the canonical directives, then regenerate.

The package's `skills/` carries only skills: the `handoff` and `iteration-limits` utilities, generated from the global rules, and generated copies of `create-pull-request` and `docs-update`, whose source is `packages/core/agent-directives/skills/`. Do not recreate roles, commands, or global policy as skill facades.

Markdown hosts share one profile per role in `agents/<role>.md` (seven roles, no orchestrator) and one command set in `commands/{fein,sonar,blitz}.md`. Do not add per-host copies. Rules stay per host because formats differ and OMP and Devin auto-discover flat files: `rules/global.md`, `rules/cursor/`, `rules/kimi-code/`, `rules/codex/`, `rules/hermes/`, and root `AGENTS.md`. Generated Codex profiles live beside the Markdown as `agents/maestria-<role>.toml`; Codex plugins cannot ship agents, so `maestria install codex` copies them to `$CODEX_HOME/agents/`. Each host manifest selects only the resources that host can load.

## Verify

```bash
scripts/sync-all
scripts/check-sync
pnpm --filter @maestria/agent-plugins test
```

Package checks verify resource completeness, selected paths, and native metadata. They do not establish live host loading, model judgment, or tool enforcement; see the [compatibility matrix](/agent-plugins/compatibility/) for dated host evidence.

## Host-Specific Checks

| Host | Also check |
| --- | --- |
| Claude Code | Run `claude plugin validate ./packages/agent-plugins --strict`. List the seven agent files and three commands explicitly, because Claude rejects directory agent selectors. Keep `model` out of profiles and preserve the read-only roles' `disallowedTools`. |
| Codex | Run `pnpm --filter maestria test` for the companion installer. Native read-only sandbox metadata belongs in the agent TOMLs; marketplace installation supplies the four skills only. |
| Cursor | Preserve `readonly` metadata and the policy rule's `alwaysApply` setting. Plugin-supplied agents did not enforce `readonly` in the 2026-10-12 probe; project `.cursor/agents/` copies did. See the [official plugin reference](https://cursor.com/docs/reference/plugins.md). |
| Kimi Code | Keep the bootstrap below the documented 32 KB limit and preserve `disallowedTools` (`Write`, `Edit`, the names Kimi registers) and `subagents` metadata. Do not add a model field the plugin-agent format does not support. See the [plugin-agent contract](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/plugins.html#plugin-agents). |
| Devin | Keep root `AGENTS.md` and `agents/` conventional; the manifest declares only `skills`. Devin has no plugin commands component or denylist, so modes are keywords and read-only is prompt-level. |
| ZCode | List the seven agents and three commands explicitly in the manifest. Unknown frontmatter keys are ignored. |
| Hermes | There is no maestria Python adapter. Keep the optional host context separate from portable activation, and smoke-test with an isolated Hermes home and the packed plugin. |
| Oh My Pi | Preserve the `package.json#omp` registration; it registers data resources, not an executable extension. The [host verification record](https://github.com/agustinusnathaniel/maestria/blob/main/docs/plugin-host-verification.md) records the OMP 18.4.8 probe and its limits. |
