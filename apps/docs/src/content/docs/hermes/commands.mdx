The plugin registers 5 slash commands in every Hermes session.

## Mode Commands

Mode state is global in `$HERMES_HOME/maestria-mode.json` and can affect other Hermes sessions sharing that home directory (a platform limitation, not session isolation). `/mode-clear` writes neutral state and stops mode prompt injection; `/mode` then reports `neutral`; a fresh installation without a state file starts in `fein`.

### `/fein`

Set the plugin to **fein** (full pipeline) mode. The orchestrator runs the complete pipeline, sequencing Thinker → Worker → Verifier roles adaptively - typically adventurer (recon), architect/planner (design/plan), builder (implementation), then reviewer (validation).

```
/fein
→ Switched to **fein** mode.
  Pipeline: adventurer / architect -> builder -> reviewer
```

The orchestrator directive runs all stages without skipping phases. This is guidance; Hermes has no native gate, so review is advisory, not mechanically enforced. Pair `/fein` with `/goal` for multi-session work: the goal persists across sessions and restores your mode on `/goal resume`.

### `/sonar`

Set the plugin to **sonar** (research) mode. Only read-only adventurer/planner research runs. No output is created.

```
/sonar
→ Switched to **sonar** mode.
  Pipeline: adventurer / architect -> STOP (read-only)
```

For a trusted top-level session, the `pre_tool_call` hook allows only inspection in sonar mode: file reading (`read_file`, `search_files`), web research (`web_search`, `web_extract`), and reading skills and prior sessions (`skill_view`, `skills_list`, `session_search`). Everything else is blocked, including `write_file`, `patch`, `terminal`, and `skill_manage`. Unknown or delegated child sessions use separate fail-closed/role-neutral policies.

### `/blitz`

Set the plugin to **blitz** (fast execution) mode. Direct blitz is limited to a literal read-only allowlist - file reading, web research, skill inspection, and transcript recall: no code changes are made directly, and no adventurer exploration or reviewer validation runs for the direct path. Delegated builder writes remain unavailable until Hermes provides an authenticated capability channel.

```
/blitz
→ Switched to **blitz** mode.
  Pipeline: builder (skip optional recon/design; required review and safety floors remain)
```

Code changes run on a trusted top-level fein session and route through review.

### `/mode`

Show the current mode and read-only status.

```
/mode
→ **Maestria Status**
  Mode: **neutral**
  Read-only: No
```

## Workflow Commands

The plugin does not register a dedicated review or plan command. Both names belong to Hermes core, and a plugin command that collides with a built-in is rejected by the loader - worse, the plugin's `pre_gateway_dispatch` hook runs before command resolution, so a colliding name would drop the message without running core's command. Use `/fein` to run the full pipeline (its reviewer and planner specialists run as pipeline stages), or the core commands below.

## Hermes Core Commands

These are available in every Hermes session regardless of plugin:

| Command        | What it does                                        |
| -------------- | --------------------------------------------------- |
| `/goal <text>` | Set a standing objective that survives across turns |
| `/goal pause`  | Pause auto-continuation without clearing the goal   |
| `/goal resume` | Resume the goal loop                                |
| `/goal clear`  | Drop the goal entirely                              |
| `/review`      | Spawn an independent subagent to review the work    |
| `/plan`        | Write a markdown implementation plan, no execution  |
| `/stop`        | Interrupt the current turn                          |
| `/resume`      | Resume a compacted session                          |

See the [Hermes Goals documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/goals) for details.
