For repository setup, changesets, and pull requests, see the [Contributing Guide](/core/contributing/). For shared methodology changes, follow the [Canonical Source Workflow](/core/contributing/#canonical-source-workflow).

## Package Boundary

`@maestria/pi` pairs a runtime extension with generated agent and skill resources. The extension owns lifecycle hooks, mode state, compaction, commands, deployment, and subagent dispatch; prompts and global rules remain in `packages/core/agent-directives/`. Keep runtime changes in the package's `src/`.

OMP has no runtime package: it consumes the portable `@maestria/agent-plugins` skills. OMP methodology changes belong to the canonical directives or the [OMP integration guide](https://github.com/agustinusnathaniel/maestria/blob/main/packages/agent-plugins/integrations/omp/README.md); OMP behavior changes are host-owned.

## Change Shared Methodology

Edit the canonical source, never generated files under `agents/` or `skills/`, then regenerate:

```bash
scripts/sync-all
```

Platform transforms stay small: Pi rewrites `@agent` to `/agent`. OMP needs no transform: it loads the portable skills unchanged. Platform-only skills need valid frontmatter and must pass the package skill validator.

## Validate

```bash
pnpm --filter @maestria/pi build
pnpm --filter @maestria/pi validate
pnpm --filter @maestria/pi test
pnpm --filter @maestria/agent-plugins test
```

Use the [Pi and OMP reference](/pi-omp/reference/) for user-facing command, dispatch, and session behavior.
