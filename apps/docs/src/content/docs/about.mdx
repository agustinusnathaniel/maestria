Maestria is a set of free, open-source plugins that give AI coding agents a shared engineering workflow: choose a route, delegate focused work, and check the result independently.

## How the Workflow Fits Together

An orchestrator coordinates seven specialists: adventurer (reconnaissance), architect (approach and trade-offs), builder (atomic implementation), diagnose (root-cause analysis), planner (phased plans), reviewer (independent review), and writer (documentation).

Two patterns guide their work: **pipeline composition** (select the thinker, worker, and verifier stages needed and pass context and evidence between them) and the **maker/checker split** (a separate reviewer checks the maker's result; no agent approves its own output).

Choose a route with [When to Use Maestria](/core/when-to-use/); [How It Works](/core/how-it-works/) covers benefits and limits, [Pipeline & Roles](/core/pipeline/) sequencing, and [Specialist Reference](/core/agents/) each role.

## Install for Your Platform

Native integrations support OpenCode, Kimi Code, Pi, Hermes, Claude Code, Codex CLI, Cursor, Prime Agent, and Oh My Pi. Install one with `npx maestria install <platform>`; the [CLI guide](/cli/getting-started/) lists platform IDs and prerequisites.

For clients that support Agent Plugins v1, [`@maestria/agent-plugin`](/agent-plugin/) provides portable skills: run `npx maestria plugin install` to stage the package, then activate it through the client's installer. Runtime permissions and delegation behavior depend on the host.

## Why Maestria Exists

I kept repeating the same personal defaults across projects: verify claims against code and docs, match effort to stakes, prefer reuse over new code, and keep output short and self-contained. Maestria packages those defaults as shared guardrails called Universal Floors in `packages/core/agent-directives/rules.md:9-16`, plus guidance for delegation and review. Safety and authorization stay on top per `packages/core/agent-directives/rules.md:61`, and the host keeps tool authority.

Projects still need local say, but bounded. Only `.maestria/workflow.md` then `.maestria/rules.md`, subordinate to core, root-only, and never waiving safety or host permissions. See `docs/adr/core/ADR-CORE-006-project-workflow-protocol.md` for that contract.

The rest is small taste that compounds: one atomic task per run, evidence before claims, and the maker/checker split from `PATTERNS.md` so no agent approves its own work. Delivery closes through completion gates in `docs/checklist.md:5-12`, with canonical directives projected per platform by `scripts/sync-all` and verified by `scripts/check-sync`.
