This page describes the `@maestria/pi` runtime extension. The Oh My Pi integration uses the shared portable package and has different activation and lifecycle behavior; see [maestria for OMP](/agent-plugins/installation/#omp).

## Workflow Modes

| Command | Behavior |
| --- | --- |
| `/fein` | Full method with reconnaissance, design, implementation, and review |
| `/sonar` | Research-only route that stops before implementation |
| `/blitz` | Fast path that skips optional reconnaissance and design while preserving required safeguards |

The modes are defined by ModeKeyword in `packages/shared/pi/src/state-core.ts`. A mode keyword anywhere in a message, outside code, sets the mode and applies it to that message; when several appear, the most restrictive wins (full-method over research-only over fast). A slash command sets the mode without a task. Either way the mode stays active for the session until another mode is set or you run `/mode-clear`.

## Reviewer Dispatch

The main loop investigates, designs, and implements each outcome itself; its `maestria_subagent` tool dispatches only the reviewer, for independent blind review, through `@gotgenes/pi-subagents`; without that extension, dispatch reports that it is unavailable. The main loop loads `diagnose` for a bug, regression, failure, or crash with an unknown cause, implements the fix, and sends meaningful changes to the reviewer for validation.

```json
{
  "agent": "reviewer",
  "task": "Review the authentication change at <commit or branch> against <acceptance criteria> without editing"
}
```

The reviewer inherits parent context. Treat handoff prompts as guidance and include the goal, constraints, acceptance evidence, and next step needed by each child.

## Session State

The extension records subagent runs and handoff history in the session. `/maestria-status` shows the active mode and handoff history. State handling across compaction and resumed sessions follows Pi's host lifecycle.

## Review Mode

`/review <target>` enters the extension's review-only path. `/review-model <id>` selects a review model, and `/restore-model` returns to the previous model and tools. Review-mode tool availability is an extension behavior; do not use a reviewer persona as a substitute for checking the active tools.

## Project Instructions

The extension checks `.maestria/workflow.md` and then `.maestria/rules.md` from the session working directory. Missing or empty files are skipped. A present but unusable file triggers a notification and a STOP banner in the system prompt that tells the agent not to execute the request until the file is fixed. See [Workflow Patterns](/core/workflow-patterns/) for precedence and carry-over.
