This page describes the `@maestria/pi` runtime extension. The Oh My Pi integration uses the shared portable package and has different activation and lifecycle behavior; see [Maestria for OMP](/agent-plugins/omp/).

## Workflow Modes

| Command | Behavior |
| --- | --- |
| `/fein` | Full pipeline with reconnaissance, design, implementation, and review |
| `/sonar` | Research-only route that stops before implementation |
| `/blitz` | Fast path that skips optional reconnaissance and design while preserving required safeguards |

Bare mode keywords at the start of a message set the mode and attach the task in one turn. Slash commands set the mode for the next message.

## Specialist Dispatch

The extension registers seven specialist agents: adventurer, architect, builder, diagnose, planner, reviewer, and writer. Dispatch uses `@gotgenes/pi-subagents`.

```json
{
  "agent": "adventurer",
  "task": "Map the authentication flow in the auth module"
}
```

The subagents inherit parent context. Treat handoff prompts as guidance and include the goal, constraints, acceptance evidence, and next step needed by each child.

## Session State

The extension records parent task IDs and specialist names in the session tree. `/maestria-status` shows the active mode and handoff history. State handling across compaction and resumed sessions follows Pi's host lifecycle.

## Review Mode

`/review <target>` enters the extension's review-only path. `/review-model <id>` selects a review model, and `/restore-model` returns to the previous model and tools. Review-mode tool availability is an extension behavior; do not use a reviewer persona as a substitute for checking the active tools.

## Project Instructions

The extension checks `.maestria/workflow.md` and then `.maestria/rules.md` from the session working directory. Missing files are skipped; unreadable present files stop the workflow with a notification. See [Workflow Patterns](/core/workflow-patterns/) for precedence and carry-over.
