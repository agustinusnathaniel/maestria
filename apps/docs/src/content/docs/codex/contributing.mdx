`@maestria/codex` is generated from the canonical directives in
`packages/core/agent-directives/`. The package adapts those directives to Codex's namespaced skill
format and pairs them with lightweight native custom-agent templates and an instruction resource;
it does not duplicate methodology content by hand.

## Package structure

```text
packages/codex/
├── .codex-plugin/plugin.json  # Hand-authored plugin manifest
├── agents/                    # Hand-authored native Codex agent templates
├── instructions/              # Hand-authored managed global orchestration block
├── skills/                    # Generated SKILL.md projections
├── sync.config.ts             # Codex-specific transforms and frontmatter
├── tests/plugin.test.ts       # Manifest and generated-file contracts
├── INSTALL.md
├── README.md
└── CHANGELOG.md
```

The Maestria CLI's local Codex marketplace is generated at install time because its adapter stages
the published npm package and points Codex at a local plugin source path. That staging directory
contains the published package and is not a second canonical source. The repository marketplace
entry below provides the direct native-install path.

The repository-level `.agents/plugins/marketplace.json` is the native Codex marketplace entry. Its
plugin source points to the published `@maestria/codex` npm package, so Codex users can install the
skills directly with `codex plugin marketplace add agustinusnathaniel/maestria` followed by
`codex plugin add maestria@maestria`. The companion CLI setup remains responsible for copying
native agent files and merging global orchestration instructions.

## Canonical source workflow

1. Edit `packages/core/agent-directives/`, never generated files under `packages/codex/skills/`.
2. Run `scripts/sync-all` from the repository root.
3. Run `scripts/check-sync` to verify every platform projection.
4. Run the package tests and the workspace checks.

```bash
scripts/sync-all
scripts/check-sync
pnpm --filter @maestria/codex test
```

## Projection rules

The Codex sync config:

- maps the 7 specialist directives to `skills/<name>/SKILL.md`;
- namespaces specialist references as `$maestria:<name>`;
- packages workflow modes as skills because the verified Codex projection surface is `skills/`;
- states read-only roles as advisory rather than claiming tool enforcement;
- keeps hooks and MCP out of the plugin manifest; native agent installation, model configuration,
  and managed `AGENTS.md` instructions belong to the companion CLI.

The `agents/` directory contains lightweight native TOML wrappers. They reference the generated
namespaced skills instead of duplicating the canonical methodology. The Maestria CLI copies these
templates into `$CODEX_HOME/agents/` as `maestria-*` roles, preserving user model, reasoning, and
service-tier settings across updates. The `instructions/AGENTS.md` resource is merged into the
active global Codex instruction file using markers, preserving unrelated user text and allowing
safe removal on uninstall.

## Validation

Run the Codex plugin-creator validator against the package and inspect the generated skill files:

```bash
python3 /path/to/plugin-creator/scripts/validate_plugin.py packages/codex
pnpm --filter @maestria/codex test
```

The verified support boundary is Codex CLI plugin skills and native CLI installation. Codex desktop
parity and runtime permission enforcement remain outside this package.
