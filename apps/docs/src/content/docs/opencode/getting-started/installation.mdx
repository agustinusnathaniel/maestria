`@maestria/opencode` adds an orchestrator, seven specialists, shared workflow rules, workflow modes, and methodology skills to [OpenCode](https://opencode.ai/v2/docs/). Install it with the maestria CLI or with OpenCode's own plugin commands.

## Compatibility

| OpenCode             | `@maestria/opencode` |
| -------------------- | -------------------- |
| V2 (2.0.28 or later) | 0.9.0 and later      |
| V1                   | 0.8.0 and earlier    |

<Aside type="caution" title="OpenCode V1">
  From 0.9.0 the package is an OpenCode V2 plugin, and OpenCode V1 cannot load it. To stay on V1,
  pin the last V1 release in your V1 config: `"plugin": ["@maestria/opencode@0.8.0"]`. The maestria
  CLI manages only the V2 plugin and refuses to install it on OpenCode V1.
</Aside>

## Prerequisites

- [OpenCode V2](https://opencode.ai/v2/docs/) 2.0.28 or later (`opencode --version`)

## Installation via CLI (Recommended)

<AllPackageManagers
  type="dlx"
  pkg="maestria"
  args="install opencode"
  comment="Install the OpenCode plugin"
/>
<AllPackageManagers type="dlx" pkg="maestria" args="status" comment="Verify installation" />

The CLI runs `opencode plugin add @maestria/opencode`, which adds the package to the global `plugins` list. See the [CLI documentation](/cli/) for more commands and options.

<details>
<summary>Alternative: OpenCode plugin commands</summary>

```bash
opencode plugin add @maestria/opencode
```

For a single project, add it to `plugins` in that project's `opencode.json(c)` or `.opencode/opencode.json(c)` instead:

```jsonc
{
  "plugins": ["@maestria/opencode"],
}
```

OpenCode installs missing packages in the background when its server starts and reloads watched config changes automatically ([OpenCode plugins](https://opencode.ai/v2/docs/plugins/)).

</details>

## Moving from OpenCode V1

OpenCode V2 reads the same config files as V1 but ignores the V1 `plugin` array, so an existing `"plugin": ["@maestria/opencode@latest"]` entry does nothing in V2. Run `maestria update opencode` (or `maestria install opencode`): it removes the maestria entry from the V1 `plugin` array and adds the package to `plugins`. Other plugins are kept, and so are comments outside the V1 `plugin` array. It also replaces a `@maestria/opencode-v2` preview entry, keeping its options.

## Verify Installation

Start a new OpenCode session. The 8 agents are ready for delegation via `@` mention, the `/fein`, `/sonar`, and `/blitz` commands are listed, and the global workflow rules are active. Read [When to use maestria](/core/when-to-use/) before choosing `orchestrator`.

## Updating

<AllPackageManagers type="dlx" pkg="maestria" args="update opencode" />

Without the CLI, run `opencode plugin update @maestria/opencode`. OpenCode also checks unpinned plugins for updates when its server starts, without changing the installed package ([OpenCode plugins](https://opencode.ai/v2/docs/plugins/)).

<Aside type="tip">
  To pin a version, run `maestria update opencode --version <version>`. It replaces the configured
  entry with `@maestria/opencode@<version>` and keeps any plugin options. OpenCode does not update
  exact versions.
</Aside>

## Uninstalling

<AllPackageManagers type="dlx" pkg="maestria" args="uninstall opencode" />

This runs `opencode plugin remove` for each global maestria entry and drops any maestria entry left in a V1 `plugin` array. Without the CLI, run `opencode plugin remove @maestria/opencode` with the exact configured specifier (for example `@maestria/opencode@0.9.0` when pinned). Remove project-level entries from that project's config by hand.
