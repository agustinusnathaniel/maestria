## Package Boundary

`@maestria/opencode` pairs a small OpenCode V2 [Effect plugin](https://opencode.ai/v2/docs/build/plugins/effect/) with methodology generated from `packages/core/agent-directives/`. The plugin loads and validates the generated agents, commands, rules, and skills once, registers them through agent, command, and skill transforms, and adds mode expansion and rules through session hooks. Platform-specific lifecycle behavior belongs in `packages/opencode/src/`; shared methodology does not.

## Change Methodology

Edit the canonical source, never generated files under `packages/opencode/agents/` or `packages/opencode/rules/`. See the [Canonical Source Workflow](/core/contributing/#canonical-source-workflow). After changing core content:

```bash
scripts/sync-all
scripts/check-sync
pnpm --filter @maestria/opencode test
```

Keep permission changes in `sync.config.ts`, and test them against the generated output. It authors each agent's permissions as a compact map and translates it to ordered OpenCode rules.

Changes that affect the host integration need the real-host probes, which run an isolated OpenCode V2 CLI with a local fake provider and write JSON evidence under `artifacts/`:

```bash
pnpm --filter @maestria/opencode build
pnpm e2e:opencode
pnpm --filter maestria build
pnpm e2e:opencode-cli
```

## Architecture

Record OpenCode-specific boundary decisions in [ADR-OC-001](https://github.com/agustinusnathaniel/maestria/blob/main/docs/adr/opencode/ADR-OC-001-tool-permission-design.md) or the relevant ADR.
