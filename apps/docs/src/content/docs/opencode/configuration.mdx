The `@maestria/opencode` plugin registers 2 agents with no model overrides, so each runs on the model OpenCode assigns by default. Overrides use the standard `agents.<name>.model` path, which works for any agent.

## Per-Agent Models

```jsonc
{
  "agents": {
    "reviewer": { "model": "<model-id>" },
  },
}
```

Edit the global config (`opencode.jsonc` or `opencode.json` in `~/.config/opencode/`, or `$XDG_CONFIG_HOME/opencode/` when set) or the project config (`.opencode/opencode.jsonc`, `.opencode/opencode.json`, or `opencode.json(c)` at the project root). Unmentioned agents keep their existing assignments.

Use `<provider>/<model-id>` with an explicit model ID copied from OpenCode's live model list, optionally followed by `#<variant>`: model IDs, availability, pricing, and aliases vary. OpenCode still accepts the V1 `agent.<name>.model` form; when both are set, the `agents` value wins ([V1 migration guide](https://opencode.ai/v2/docs/migrate-v1/)).

## Model Inheritance

Model assignment follows a chain. In OpenCode V2, a primary agent uses the session's selected model, and a subagent without its own model inherits the model of the session that launched it ([agents documentation](https://opencode.ai/v2/docs/agents/)).

The reviewer is a subagent of the main loop, so it inherits the main loop's model unless overridden individually. Read [When to use maestria](/core/when-to-use/) before assigning the same model to every agent.

<Aside type="tip">
  To put the main loop and reviewer on the same model, set{' '}
  <Code code="agents.maestria.model" lang="jsonc" />. Add a `agents.reviewer.model` entry only to
  diverge the reviewer.
</Aside>

## Selective Assignment

The CLI validates a model ID against OpenCode's live model list and changes only the named agents. It writes `agents.<name>.model` and removes a V1 `agent.<name>.model` for the same agent so the two cannot conflict:

<AllPackageManagers
  type="dlx"
  pkg="maestria@latest"
  args="configure opencode --global --set reviewer=<model-id>"
/>

See the [configure reference](/cli/commands/#configure) for supported platforms and options.

## Model Field in Markdown Frontmatter

Custom agents defined locally can set the model in the agent's Markdown frontmatter:

```markdown
---
name: my-custom-agent
model: <model-id>
---
```

This works the same as the `agents.<name>.model` config entry.

## Project-Level Config

Project config (`.opencode/opencode.jsonc`) merges with global config (`~/.config/opencode/opencode.jsonc`); project settings take precedence.

## Disabling Workflow Modes

`modes.disabledKeywords` accepts a denylist of mode keywords in the plugin options. Disabled keywords are no longer detected in prompts; their slash commands stay available:

```jsonc
{
  "plugins": [
    {
      "package": "@maestria/opencode",
      "options": { "modes": { "disabledKeywords": ["blitz"] } },
    },
  ],
}
```

Invalid options are logged and ignored, and the plugin runs with defaults.

Mode detection and precedence are documented under [Modes](/core/agents/#modes).
