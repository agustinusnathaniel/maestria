The `@maestria/opencode` plugin registers 8 agents with no model overrides, so each runs on the model OpenCode assigns by default. Overrides use the standard `agent.<name>.model` path, which works for any agent.

## Per-Agent Models

```jsonc
{
  "agent": {
    "adventurer": { "model": "<model-id>" },
    "writer": { "model": "<model-id>" },
  },
}
```

Edit either `~/.config/opencode/opencode.jsonc` (global) or `.opencode/opencode.jsonc` (project-level). Unmentioned agents keep their existing assignments.

Use `<provider>/<model-id>` with an explicit model ID copied from OpenCode's live model list: model IDs, availability, pricing, and aliases vary.

## Model Inheritance

Model assignment follows a chain. From the OpenCode documentation:

> If you don't specify a model, primary agents use the globally configured model while subagents will use the model of the primary agent that invoked the subagent.

The 7 specialists are subagents of the orchestrator, so they inherit the orchestrator's model unless overridden individually. Read [When to use Maestria](/core/when-to-use/) before assigning the same model to every agent.

<Aside type="tip">
  To put every specialist on the same model, set{' '}
  <Code code="agent.orchestrator.model" lang="jsonc" />. Add entries only for the agents you want to
  diverge.
</Aside>

## Selective Assignment

The CLI validates a model ID against OpenCode's live model list and changes only the named agents:

<AllPackageManagers
  type="dlx"
  pkg="maestria@latest"
  args="configure opencode --global --set adventurer=<model-id>,writer=<model-id>"
/>

See the [configure reference](/cli/commands/#configure) for supported platforms and options.

## Model Field in Markdown Frontmatter

Custom agents defined locally can set the model in the agent's Markdown frontmatter:

```markdown
---
name: my-custom-agent
model: <model-id>
---
```

This works the same as the `agent.<name>.model` config entry.

## Project-Level Config

Project config (`.opencode/opencode.jsonc`) merges with global config (`~/.config/opencode/opencode.jsonc`); project settings take precedence.

## Project Customization (.maestria/)

When the project root contains `.maestria/workflow.md` or `.maestria/rules.md`, the plugin injects the full content of each file that exists fresh on every model call in deterministic order (workflow first, then rules). The root resolves from the SDK project worktree, then the worktree path, then the session directory; a `/` sentinel is skipped. Projects without these files see no behavior change. Edits apply on the next call with no restart, for primary and subagent calls including after compaction.

This injection runs through `experimental.chat.system.transform`, not `config.instructions`. A project file that exists but cannot be used fails the call loudly instead of running with silently absent config. Project guidance stays subordinate: it may replace configurable workflows but never waives safety, authorization, or host permissions. See [Project-Specific Workflows](/core/workflow-patterns/#project-specific-workflows) for the shared contract that applies on every host.

## Disabling Workflow Modes

`modes.disabledKeywords` accepts a denylist of mode keywords in the plugin options:

```jsonc
{
  "plugin": ["@maestria/opencode", { "modes": { "disabledKeywords": ["blitz"] } }],
}
```

Mode detection and precedence are documented under [Modes](/core/agents/#modes).
