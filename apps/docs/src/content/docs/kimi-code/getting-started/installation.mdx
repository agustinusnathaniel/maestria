@maestria/kimi-code is a declarative Kimi Code plugin. It contributes skills, namespaced workflow commands, and a system prompt. There is no build step.

## Prerequisites

- Kimi Code v0.38.0 or later for the verified plugin registry, systemPromptPath, and AgentSwarm behavior.
- Node.js 22.12 or later and npm when using the Maestria CLI.
- Kimi's own prerequisites when installing directly.

## Install via the Maestria CLI

This is the recommended path:

<PackageManagerCommands
  type="dlx"
  pkg="maestria"
  args="install kimi-code"
  comment="Install for Kimi Code"
/>

Check the native plugin record:

<PackageManagerCommands type="dlx" pkg="maestria" args="status" comment="Check installation" />

The CLI downloads the npm package, installs it through Kimi's plugin manager, and preserves existing plugin records and global instructions. Start a new Kimi Code session after installation so the session-start skill and system-prompt contribution load.

```text
/reload
/new
```

## Install manually

Use this only when you need to control the package extraction or invoke Kimi's native installer yourself:

```bash
npm pack @maestria/kimi-code@latest --pack-destination /tmp
mkdir -p /tmp/maestria-kimi-code
tar -xzf /tmp/maestria-kimi-code-*.tgz -C /tmp/maestria-kimi-code --strip-components=1
```

Then install the extracted directory from a Kimi Code session:

```text
/plugins install /tmp/maestria-kimi-code
```

The CLI path and the manual path both produce the same Kimi-managed plugin. Delete the temporary tarball and directory when you no longer need them.

## Optional Session Controls

Maestria does not add hooks or permission rules to Kimi Code. Add them only if your workflow needs them.

- Hooks can block selected commands, add a per-turn reminder, or observe compaction.
- Permission rules apply to the whole Kimi session, not to one persona. A deny rule intended for review also blocks builder and writer work in that session.
- Persona text alone is advisory. It does not make reviewer or adventurer read-only.

Treat custom hooks as executable code and review them before enabling them. Keep the default installation path free of optional controls.

## Verify the Installation

In Kimi Code, run:

```text
/plugins list
/plugins info maestria
```

Confirm that the plugin is enabled and that its session-start skill is orchestrator. In a new session, ask the orchestrator to list its available specialists.

Kimi limits each plugin system-prompt file to 32 KB. The packaged SYSTEM.md is tested against that limit. If AgentSwarm is unavailable, verify that Kimi Code is v0.38.0 or later.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Plugin is missing | Run /plugins list and /plugins info maestria, then restart Kimi Code |
| Orchestrator does not load | Confirm sessionStart.skill is orchestrator and start a new session |
| System prompt is truncated | Keep long detail in specialist SKILL.md files; Kimi enforces the 32 KB file limit |
| Reviewer can edit | Configure session-wide permission rules; the persona prompt is not enforcement |

## Update

<PackageManagerCommands type="dlx" pkg="maestria" args="update kimi-code" />

To pin a version:

<PackageManagerCommands type="dlx" pkg="maestria" args="update kimi-code --version 0.5.2" />

Updates replace the managed package. Back up local edits before updating.

## Uninstall

<PackageManagerCommands type="dlx" pkg="maestria" args="uninstall kimi-code" />

Or from a Kimi Code session:

```text
/plugins remove maestria
```

If you added custom hooks or permission rules, remove those blocks from ~/.kimi-code/config.toml separately.
